## Official interface verification

- 使用固定 `https://api.deepseek.com/chat/completions`、model=`deepseek-flash`、非流式，`response_format={"type":"json_object"}`。官方Chat Completions文档支持JSON对象模式，不保证ThesisLab契约；因此响应仍送入既有 `research.validate_draft`。[官方API](https://api-docs.deepseek.com/api/create-chat-completion/)
- 设置 `thinking={"type":"disabled"}`、`max_tokens=4000`，避免默认思考模式与默认输出上限。官方当前列别名对应DeepSeek-V4.1-Flash；这只是文档信息，实际返回model／fingerprint／版本需真实请求核验。若仅返回别名，精确底层版本仍UNVERIFIED。[官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)
- 401认证失败、402余额不足、403权限拒绝、429限流或其他非200均立即暂停本次会话；不自动重试、不充值、不备用模型、不查询余额另耗请求。[官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)

## Before real calls

实际调用必须先由用户在对话里明确批准请求次数及输出上限。程序开关仅落实已批准预算，**不是批准本身**。未获批准时不运行下列带授权开关的命令。

```bash
# ONLY after explicit human approval: three cases, one request each initially.
.venv/bin/python tools/run_deepseek_validation.py \
  --authorize-budget --max-requests 6 --max-output-tokens 4000 \
  --cases state causal attribution --run-dir .local/deepseek-m25
```

密钥必须由用户安全配置到本地进程环境 `DEEPSEEK_API_KEY`。本项目不自动读.env、Keychain、私人配置，也不打印环境。`.env.example`只有空字段，不能把真实密钥填入模板。没有密钥时停止，不寻找其他凭证。已有环境变量不被程序改写；请求内局部凭证引用在finally释放，不能承诺Python字符串物理内存擦除。

仅发送：本项目公开的通用契约指令与三句“估值回落，但基本面未恶化。”“某项外部变化将影响产业链利润分配。”“盈利改善主要来自主营业务。”不读取财报／研究报告进入提示词，也不附带供应商响应、数据库或私人文件。

固定run-dir保存ledger与运行锁；同一批准预算最多6个占用槽，失败/不确定请求也占用。默认先3次各一例；不自动纠错重发。后续有必要的人工触发调用仍从同一ledger扣数，不创建新目录绕过余额。发送前持久化reservation；持久化失败不发请求；中断保留槽并要求审核，不能当未发送自动补发。

响应只在完整取得后解析：最大2MB、Content-Length一致、identity编码、UTF-8 envelope、单个完成结果、finish_reason=stop。IncompleteRead、异常压缩、截断、权限／余额等情况停止会话。无效JSON、重复键、非有限JSON数字、无效span／契约等拒绝候选，无自动修复。错误信息只留受控类型，不保存HTTP错误正文／请求头／密钥／reasoning_content。

## Reviewable candidate, not a verified fact

每次成功候选导出 `.local/deepseek-m25/attempt-N-<case>.candidate.json`、`.review.md` 和 `.semantic-review.json`，并以 `origin=model_candidate` 保存到私有candidates.sqlite。无效模型文本只放`.rejected.txt`隔离，不变成Evidence。用户可编辑candidate.json，使用既有M2 `draft/confirm` 流程重审；未解决关键澄清不能确认，新增suggestion必须接受或删除。

M2 Schema不能证明语义。人工八维检查：原文保义、原文归属、事实前提与必要条件、因果／归因、竞争解释与辨别、新假设suggestion、证伪／削弱／重验、计划与断言分离。逐项留claim ID、引用及PASS/FAIL/UNVERIFIED/N/A；另给总体结论。不能用另一次模型Judge或span覆盖替代人工检查。

本次三主张都缺观察窗口。现有M2 executable Condition要求具体ISO起止日期，不臆造日期以凑Schema。模型应在condition_gap与qualifiers.change_conditions_proposed给具体路径及待确认窗口，这些只是建议；待用户澄清后才转入现有conditions。报告必须区分条件建议可审查与条件可执行。此处理没有改变M2领域模型。
